## Available Now

The provider contains 6,106 feature instruments. All 6,106 instrument
directories contain the following daily fields:

```text
open
high
low
close
volume
amount
vwap
change
factor
adjclose
```

Three sample instruments were checked over 2021-2023 and all tested fields had
100% coverage in the returned trading-date rows.

The provider also contains point-in-time instrument membership files for:

```text
csi300
csi500
csi800
csi1000
csiall
all_stock_shsz
all_stock_shsz_liquid2000
```

Benchmark feature directories are available for CSI300, CSI500, and CSI1000.
Instrument files include start/end intervals, so listing age and point-in-time
eligibility can be derived.

## Missing Data Layers

The current provider does not contain directly usable fields for:

```text
industry classification
total market capitalization
float market capitalization
fundamental statements/ratios
analyst expectations
```

Consequences:

- Alphalens/jqfactor group analysis can run only after a point-in-time industry
  classification source is selected.
- Size-neutral IC, cap-weighted quantile returns, and Barra-style size exposure
  should not be reported yet.
- Value, quality, profitability, and growth factor families should wait for a
  fundamental data source and licensing decision.

## Existing External Layers

The project already provides tradability and data-quality context outside the
Qlib feature files:

```text
can_buy
can_sell
liquidity_bucket
tradability_score
data_quality_status
```

These remain mandatory prefilters for all external evaluator systems.

## Recommended Order

1. Add benchmark-return, universe-membership, and listing-age adapters using
   data already available in the provider.
2. Research open-source or freely accessible point-in-time industry and market
   cap data sources, including license and survivorship-bias implications.
3. Enable industry/group-neutral open-source evaluation only after those data
   sources are validated.
4. Expand price/volume factor pools from Qlib Alpha158/Alpha360, `ta`, and
   Alpha101 while keeping missing-data-dependent factor families disabled.
5. Add fundamental factors only after a separate fundamental data decision.

This order allows factor-pool expansion without pretending that industry,
size, or fundamental controls already exist.
